## 1. Pfleger-Verwaltung

> Erstellt User Stories für die Verwaltung von Pflegekräften: mindestens Anlegen, Anzeigen, Ändern, Löschen.

### User Story 1: _Pflegekraftverwaltung_

**User Story**

> Als Wohnbereichsleiter möchte ich Pflegekräfte im System verwalten können, um den Personaleinsatz im Pflegeheim effizient zu organisieren..

**Akzeptanzkriterien**

| Nr. | Kriterium |
|-----|-----------|
| A_1 | Eine Pflegekraft besteht aus PflegekraftID, Vorname, Nachname, Geburtsdatum, Telefonnummer und Berufsbezeichnung|
| A_2 | Alle Pflegekräfte werden in einer tabellarischen Übersicht angezeigt|
| A_3 | Neue Pflegekräfte können angelegt werden|
| A_4 | Bestehende Pflegekräfte können bearbeitet werden|
| A_5 | Pflegekräfte können gelöscht werden|
| A_6 | Pflichtfelder dürfen nicht leer gespeichert werden|
| A_7 | Änderungen werden dauerhaft in der Datenbank gespeichert|
| A_8 | Gelöschte Pflegekräfte erscheinen nach Neustart nicht mehr|

**Tasks**

| Nr.  | Task |
|------|------|
| T_1  | Modelklasse Pfleger erstellen|
| T_2  | Datenbanktabelle pfleger erstellen|
| T_3  | PflegerDao implementieren (CRUD Operationen)|
| T_4  | Connection über DaoFactory anbinden|
| T_5  | TableView für Pflegekräfte in FXML erstellen|
| T_6  | Funktion „Pflegekraft anlegen“ implementieren|
| T_7  | Funktion „Pflegekraft bearbeiten“ implementieren|
| T_8  | Funktion „Pflegekraft löschen“ implementieren|
| T_9  | Eingabevalidierung für Pflichtfelder implementieren|
| T_10 | Controller PflegerController erstellen|


**Testfälle**

**TF1: Pflegekraft anlegen**

| | |
|---|---|
| **Vorbedingung** | Pflegekraftverwaltung ist geöffnet|
| **Testschritte** | 1. Alle Pflichtdaten eingeben 2. „Speichern“ klicken|
| **Erwartetes Ergebnis** | Pflegekraft wird in Tabelle angezeigt und in DB gespeichert|

**TF2: Pflegekraft bearbeiten**

| | |
|---|---|
| **Vorbedingung** | Mindestens 1 Pfleger vorhanden|
| **Testschritte** | 1. Pflegekraft auswählen 2. Daten ändern 3. Speichern|
| **Erwartetes Ergebnis** | Änderungen werden in Tabelle und Datenbank übernommen|

**TF3: Pflegekraft löschen**

| | |
|---|---|
| **Vorbedingung** | Pfleger existiert|
| **Testschritte** | 1. Pflegekraft auswählen 2. Löschen bestätigen|
| **Erwartetes Ergebnis** | Pflegekraft wird aus Tabelle und Datenbank entfernt|

## 2. Datenschutz-Fixes

### Priorisierungs-Begründung

> Wir Priorisieren den Log-In, da es eine wesentlich verbesserung der Risikominimierung darstellt, vor allem in verbindung mit hochsensiblen Patientendaten. Es besteht ohne login ein hohes Missbrauch- und Sicherheitsrisiko. Außerdem zählt es zu den Grundlegenden DSGVO-Anforderungen

### User Story 1: _Titel_

**User Story**

> Als Pflegekraft möchte ich mich mit meinen Zugangsdaten in der Anwendung anmelden können, um auf die für meine Arbeit benötigten Patienten- und Behandlungsdaten zugreifen zu können. 

**Akzeptanzkriterien**

| Nr. | Kriterium                                                                                                  |
|-----|------------------------------------------------------------------------------------------------------------|
| A_1 | Eine Anmeldung erfolgt über einen Benutzernamen und Passwort                                               |
| A_2 | Beide Felder sind mandatory                                                                                |
| A_3 | Bei zullässigen Anmeldedaten wird die Hautansicht/Startseite der Anwendung geöffnet                        |
| A_4 | Bei unzulässigen Anmeldedaten erscheint eine Fehlermeldung                                                 |
| A_5 | Das Passwort wird während der Eingabe nicht als Klartext angezeigt                                         |
| A_6 | Nach erfolgreicher Anmeldung bleiben die Daten der Pflegekraft während der Nutzung der Anwendung verfügbar |
| A_7 | Nach dem Schließen der Anwendung muss sich erneut angemeldet werden                                        |

**Tasks**

| Nr. | Task |
|-----|------|
| T_1 |Modelklasse für Pflegekräfte mit Zugangsdaten erweitern |
| T_2 |Datenbanktabelle um Informationen für Benutzeranmeldungen ergänzen |
| T_3 |Datenzugriff für das Überprüfen von Zugangsdaten implementieren |
| T_4 |Login-View mit Eingabemöglichkeiten für Benutzername und Passwort erstellen |
| T_5 |Controller für die Verarbeitung der Anmeldung erstellen |
| T_6 |Funktion zum Wechsel von der Login-Ansicht zur Hauptansicht implementieren |
| T_7 |Fehlermeldungen für ungültige Eingaben oder falsche Zugangsdaten implementieren |
| T_8 |Speicherung der aktuell angemeldeten Pflegekraft während der Programmausführung umsetzen |

**Testfälle**

**TF1: Erfolgreiche Anmeldung**

| | |
|---|---|
| **Vorbedingung** |Eine Pflegekraft mit gültigem Benutzernamen und Passwort ist in der Datenbank gespeichert |
| **Testschritte** |Der User gibt Benutzernamen und Passwort ein. 2. Der User bestätigt die Anmeldung |
| **Erwartetes Ergebnis** |Die Hauptansicht der Anwendung wird geöffnet und die Pflegekraft ist angemeldet |

**TF2: Anmeldung mit falschem Passwort**

| | |
|---|---|
| **Vorbedingung** |Eine Pflegekraft ist in der Datenbank gespeichert. |
| **Testschritte** |1. Der User gibt den korrekten Benutzernamen ein. 2. Der User gibt ein falsches Passwort ein. 3. Der User bestätigt die Anmeldung. |
| **Erwartetes Ergebnis** |Die Anmeldung wird verweigert und eine Fehlermeldung erscheint. |

**TF3: Anmeldung mit leerem Eingabefeld**

| |                                                                                   |
|---|-----------------------------------------------------------------------------------|
| **Vorbedingung** | Die Login Ansicht ist geöffnet                                                    |
| **Testschritte** | 1. Der User lässt Benutzername oder Passwort leer. 2. Der User bestätigt die Anmeldung |
| **Erwartetes Ergebnis** | Die Anmeldung wird nicht durchgeführt und ein Hinweis auf die fehlenden Eingaben erscheint.   |
